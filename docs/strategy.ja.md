# 監視戦略

## 目的

買い場を探して毎日相場をチェックする代わりに、Drawdown Watcherは本当に意味のある、
大きくてめったに起きない下落を監視します。金融危機、2020年や2022年のような暴落、
2025年の関税ショックのような急落、あるいはこの先に起きる何かです。

こうした出来事を予測しようとはしません。パニックの最中ではなく、平常時にあらかじめ
決めておいたルールを機械的に監視します。

利用者は普段相場を見ていない前提なので、要は「相場を見るべきときに知らせてもらう」
ことです。知らせる内容は1つではなく、次の4段階に分かれます。

1. **相場を見ておけ** — 本格的な下落が始まった（`DRAWDOWN_MODE_ENTER`。局面の途中で
   再び下落した場合は`RENEWED_DECLINE`。後述）。
2. **そろそろ底かも** — 設定したより深いLevelに達した（`LEVEL_TRIGGER`）。
   状況を知らせるだけで、行動を促すものではない。
3. **底を打った** — 安値からの反発が確定した（`RECOVERY_CONFIRMED`）。
   買うきっかけとして想定している通知。
4. **まだ持っていていい / 上昇が終わったかも** — 底打ちの後、反発がはっきり
   一段落するまで追跡する（`UPTREND_ARMED`、`UPTREND_EXIT`。後述の「底打ちの後」
   を参照）。売るきっかけとして想定している通知で、同じくらい大事なのは、それまでは
   *売らない*ためのものでもあること。

(3)で底値ちょうどを捉えることは、はっきり目的外です。底から10〜20%上がってから
知らせても全く問題ありません。大事なのは(3)が信頼できることです。本当の下落が
来る直前に「底を打った」と誤報することこそ、早すぎる・遅すぎるよりも徹底して
防ぐべき失敗です。

## 基準高値

平常時の基準高値は**過去52週の最高終値**です。新しい高値をつければ自動で更新されます。

```text
52週最高終値: $230
現在の終値:   $207

ドローダウン = 207 / 230 - 1 = -10.0%
```

日中の価格ではなく日次の終値だけを使います。1日だけの急変動を除外でき、
バックテストしやすく、APIの呼び出しも減らせます。数ヶ月続く下落を捉えるのに、
リアルタイムの精度は必要ありません。

上場から最初の52週間は、本当の基準高値とはみなしません。上場時の価格は
ピークではなく、それをピークとして扱うと、いきなり偽のドローダウンが発生します
（SPXLでは2008年の上場から11営業日目に誤って判定されました。ちょうど2008年の
暴落と重なった時期です）。`rolling_high`/`all_time_high`は52週分の履歴が
揃うまで不明値（`NaN`）を返し、state machineはその期間は判定を行いません。

## Drawdown Mode

52週の移動高値には問題があります。1年以上続く下落相場では、暴落前の高値が
やがて52週の範囲から外れ、相場が回復していないのに基準価格がじわじわ
下がってしまいます。

これを避けるため、銘柄ごとに設定した`watch_threshold`に達した時点で基準高値を
その値で**ロック**し、Drawdown Modeに入ります。以降、局面が終わるまで、Levelなどの
ドローダウンは移動する52週の範囲ではなく、このロックした値を基準に計算します。

```text
52週最高終値:    $200
watch_threshold: -20%

終値 $160  →  -20%に到達  →  基準高値を$200でロック
```

## どこまで深く設定するか: 調整ではなく暴落を捉える

すべての下落を捉えることが目的ではなく、取りこぼしがあっても構いません。
狙いは数年に1度起きる規模の下落で、ほぼ毎年起きる通常の調整ではありません。

このため、`watch_threshold`はかなり深く設定する必要があります。3倍レバレッジETFは、
本当の暴落とは関係ない20〜30%の下落が日常的に起きます。数年に1度の頻度にするには、
広く分散したインデックスファンドなら妥当な「-10% / -20%」程度より、はるかに深い
閾値が必要です。具体的にどこまで深くするかは銘柄ごとの調整の問題で、設計の一部では
ありません。`src/threshold_sweep.py`で、候補の深さごとに過去にDrawdown Modeが何回
発生したかを確認し、`src/backtest.py`でその局面の中身を確認してください。
`config/config.example.yaml`の値は例示用です。

調整するときの注意点:

- 各銘柄の過去データには、対象になる暴落が数回分しかないため、それに合わせすぎ
  （過学習）やすい。閾値を数ポイント動かしても、捕捉する暴落が変わらないことを
  確認する。
- レバレッジETFは歴史が短く（ほとんどが2008年以降の上場）、しかもその期間は
  異例なほど強い上昇相場だった。`--synthetic`（`src/backtest.py`・
  `src/threshold_sweep.py`・`src/exit_sweep.py`で使える）を付けると、原指数から
  日次で3倍にリバランスした合成系列（`src/synthetic.py`。S&P 500なら1960年まで遡る）
  で検証でき、1973〜74年、1987年、2000〜2002年、2008年の暴落全体、長い横ばい相場も
  含められる。両方で確認すること。ETF自体の期間でしか通用しないルールは、1回の
  上昇相場に合わせただけのものになる。
- 閾値はconfigにあるので、コードを変えずに、新しいデータで後から調整し直せる。

## Level

各銘柄には`watch_threshold`より深いLevelを複数設定でき、Drawdown Mode中の
状況把握のためだけに追跡します。行動を促す通知ではない（後述のRecoveryを参照）ので、
複数日の滞在確認は行いません。当初は、1日だけのノイズを除くため、Levelを3〜5営業日
下回り続けたら確定する案がありました。しかし実際の暴落局面でバックテストすると、
Levelを下回っていた期間は1営業日から500営業日超までばらばらで、一貫した傾向が
ありませんでした。固定日数のルールにすると、本物の通知が遅れるうえ、2日だけ下回って
すぐ反発したケースでは通知そのものが出なくなります。そのため不採用にしました。

```yaml
SPXL:
  watch_threshold: -30
  levels: [-40, -50, -60]  # 例示用の値
```

## Recovery

これは3段階目の「底を打った」で、行動を促すための唯一の通知です。そのため、
速さよりも信頼性を優先します。

最初の版は、安値から`recovery_threshold`分反発した時点で1回だけ通知していました。
これは3倍レバレッジETFでは逆効果でした。実際の暴落局面（SPXL/SOXL/TECLの2008年、
2011年、2020年、2022年）でバックテストすると、暴落の最中に1〜2日で+15%反発する
一時的な戻り（デッドキャットバウンス）はよくあることで、終わったサインでは
ありませんでした。2020年の暴落では、SPXLの最初の+15%の反発は下落開始からわずか
数日後で、その後本当の底までさらに約60%下落しました。さらに悪いことに、1局面で
1回しか通知しないため、その早すぎる通知が*唯一の*通知になり、数ヶ月後の本当の底は
何も知らされずに過ぎていました。相場を見ていない人にとって、「終わったよ」と
言われた後に、何の連絡もなく暴落が続くのは最悪の失敗です。

そこで現在は、次の2つを組み合わせて確定し、何度でも通知し直せるようにしています。

- **大きさと時間の両方の条件**: 価格が安値から`recovery_threshold`（+15%）以上
  上にあり、*かつ*その安値が`recovery_confirm_days`（10）営業日の間更新されて
  いないこと。大きさだけでは不十分で、新安値の直後の急反発にはまだ意味がない。
- **確定は取り消せる**: 確定した後に、その安値を下回る終値が出たら確定を取り消し
  （`RECOVERY_UNDERCUT`。「さっきの底打ちは間違いで、まだ下がっている」）、
  新しい安値からあらためて確定し直す。

バックテストした過去のすべての局面で、局面の*最後の*確定がその後に取り消された
ことは一度もありませんでした。つまり最後の確定は必ず本当の底の後に出ており、
これこそこの仕組みで保証したい性質です。きれいなV字型の暴落（2018年、2020年、
2025年）はたいてい1回で確定し、だらだら続く下落（2011年、2022年）では、本当の底に
たどり着くまで確定→取り消しを2〜3回繰り返すことがあります。最悪の局面では1〜2年で
何回か通知が来ることになりますが、自信満々に「終わった」と誤報するよりは良いので、
許容しています。

`recovery_threshold: 15`と`recovery_confirm_days: 10`（初期値）は出発点であり、
銘柄ごとに調整した結果ではありません。上の過学習の注意点を参照してください。

## 長い下落局面の途中での再アラート

だらだら続く下落では、基準高値に戻らないまま何年もDrawdown Modeが続くことが
あります（SOXLの2022年の暴落は、2026年4月まで元に戻りませんでした）。そのままでは、
Drawdown Modeが終わるまで通常の52週高値の追跡に戻らないため、その間にどれだけ
新たな下落が起きても、新しい「相場を見ておけ」は何も来ません。

最初の版は、元の（古い、ロックされた）基準高値に対して`watch_threshold`を下回り
直すたびに再通知していました。これは実際にはノイズが多すぎました。その線の近くで
価格が普通に上下するたびに発火し、そもそも局面に入るきっかけになった暴落の
最中にも発火し、本当の`RECOVERY_CONFIRMED`が出た後も、確定した底の前後で発火し
続けました。レバレッジETFと非レバレッジETFのいくつかでバックテストしたところ、
銘柄ごとに十数回以上発火し、そのほとんどは新しい下落ではありませんでした。

そのため現在は、`RECOVERY_CONFIRMED`の*後*だけを対象にしています。底が確定したら、
それ以降についた高値を別に追跡し、元の基準高値ではなく*その*高値から
`watch_threshold`%下落したら、1段階目の「相場を見ておけ」（`RENEWED_DECLINE`）を
再通知します。底が一度も確定していないうちは、元の基準高値に向かって下がるのは
同じ暴落が続いているだけで新しい暴落ではないので、「再」下落とはみなしません。

これは新しいサブ局面の開始として扱います。基準高値をその底打ち後の高値でロックし
直し、LevelとRecoveryの判定もリセットするので、いつもの3段階の流れ（相場を見ておけ
→ Level → 底を打った）がもう一度そのまま流れます。*元の*暴落の基準高値（レバレッジ
ETFでは1桁近く上にあることもある）まで下がりきるのを待たずに、通知できるように
するためです。この版で同じ銘柄を再度バックテストすると、誤報はゼロで、正しい発火が
1回だけありました。SOXLの2025年初めの、2022年の局面とは別の深刻な下落です。
2022年の局面の基準高値からは遠すぎて検知できず、価格が2022年の安値を下回っても
いなかったので、上のRecoveryの判定でも捉えられなかったケースです。

ロックし直した基準高値は、新しいサブ局面のLevelとRecoveryの判定にだけ使い、
Drawdown Mode自体がいつ終わるかの判定には*使いません*。`NORMAL_RESUME`は、局面が
始まったときの*元の*基準高値を回復したときだけ発火します。この値は別に保持し、
ロックし直すことはありません。もし（より低い）ロックし直した値で局面を終わらせると、
本物の不具合になります。元のより高い基準高値はまだ52週の範囲内に残っていることが
多いため、局面を終えた翌日に`reference_high_series`を引くと古くてずっと高い値が
返り、価格が回復の途中なのに、すぐに誤った`DRAWDOWN_MODE_ENTER`が再び発生します。
今のバックテストでこれが表に出ないのは、SOXLの2025年のサブ局面が終わる頃には、
2022年の元の高値がすでに52週の範囲から外れていたからにすぎません。2008年のように
「暴落→反発→暴落」が1年以内に起きる相場では、まさにこの失敗が起きます。そして
それこそが、このツールで捉えたい種類の相場です。

## 底打ちの後: 上昇を持ち続ける

底打ちの判定は半分にすぎません。もう1つよくある失敗は、せっかくの良い買い場で
早く売りすぎることです。底近くで買い、2倍で売り、その後5倍まで伸びるのを見ている
ことになります。めったに相場を見ない人には、さらに別の問題もあります。何ヶ月かぶりに
証券口座を開いても、天井はどこだったか、どこまでの下落なら持ち続けるはずだったか、
といったルール自体を思い出すのが難しいことです。

そこで、底打ちの後もツールが反発を追跡し続け、ルールを具体的な数字で示します。
追跡は`RECOVERY_CONFIRMED`の終値（「基準価格」）から始めます。実際の購入価格は
不要なので、個人のポジション情報は一切扱いません。追跡は2段階です。

1. **基準価格の`hold_until_multiple`（2倍）までは持ち続ける。** それまでは価格に
   よる売りの条件を一切設けません。上昇の序盤は底と同じくらい値動きが荒く、
   この段階から天井からの下落で売る条件を入れると、何度も振り落とされます。
   2倍に達すると`UPTREND_ARMED`を通知します。あえて利益を確定したくなる気持ちが
   一番強いタイミングで、「ここからのルールは、天井から`trail_from_peak`%下がる
   までは持つ」と伝えるためです。
2. **それ以降は、基準価格以降の最高終値から`trail_from_peak`%下がったら終了**
   （`UPTREND_EXIT`、理由は`trail`）。「上昇が終わったかも」という通知です。
   天井そのものでは決して売れません。利益の一部を手放すのは、残りの上昇から
   振り落とされないための代償です。

1段階目には例外が1つあります。2倍に届く前に底打ちの判定そのものが取り消された
（`RECOVERY_UNDERCUT`）場合は、持ち続ける前提が崩れたので追跡を終了します
（`UPTREND_EXIT`、理由は`undercut`）。次の底打ちで、新しい追跡が始まります。

追跡はDrawdown Modeとは独立しています。持つ価値のある上昇は、たいてい局面の元の
基準高値（`NORMAL_RESUME`）をはるかに超えて続くので、それを超えても追跡を続けます。

底打ちから売るまでの1往復ごとの成績を掛け合わせて（売った後は次の底打ちまで現金）、
売りのルールを比べたバックテストで分かったこと:

- **早く売るのが一番損をする。** 最初から浅い基準で天井からの下落で売ると、単純に
  2倍で売るよりも悪く、長く持つよりはるかに悪い結果になった。上昇の序盤の荒い
  値動きや、だらだら続く下落相場で振り落とされるため。
- **2倍までは持ち、その後に天井からの下落で売る条件を入れる**と、この振り落としの
  大部分がなくなり、レバレッジETFでは2倍で売るのも、最初から天井からの下落で
  売るのも上回った。
- **ただし「何があっても2倍まで持つ」は、長期で見ると致命的。** ETF自体の期間
  （2008年以降）では最も良く見えたが、合成系列では、2000〜2002年の間に出た底打ちで
  買うと、来ない2倍を待ちながら下落の最後まで持ち続け、数十年かかるか、
  半導体の3倍ファンドではほぼゼロになった。底打ちが取り消されたら降りるように
  すると、この問題は解決する。代わりに、誤った底打ちのたびに小さく限定的な損失
  （たいてい-10〜-30%）が出て、悪い年（2008年）には何回か続くことがある。
- 結果は`trail_from_peak`の正確な値に敏感で、各銘柄には完全なサイクルが数回分しか
  ない。おおよその幅として扱い、実データと合成系列の両方で確認すること。

通知の合間には、定期的なHeartbeatで、追跡中の各銘柄の状況を伝えます。例えば
「保有継続（2倍到達済み）。天井 $245.10（2026-08-14）、現在そこから-9.7%。
売りライン $171.57（あと22.5%下）」のように示し、「何をすればいいんだっけ？」の
答えが、記憶ではなく常に最新の通知にある状態にします。

## このツールではないもの

- 暴落の予測ツールではない。
- 投資助言や、投資額を決めるツールではない。すべての通知は利用者があらかじめ
  設定したルールで、ツールはそれを当てはめて具体的な数字で示すだけ。
- 特定の銘柄に依存しない。閾値はコードではなく設定値。
